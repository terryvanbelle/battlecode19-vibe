## 1. Training method in each, and how it evolved

### 1a. Common skeleton (both years)
- Phase 0 before strategy, in order: rules digest verified against engine source; headless
  runner with bare `java`, parallel; determinism check; replay -> text dumper; bytecode monitor
  in the bot from line 1; snapshot/mirror/sparring tools; unit tests for bot + tools; charts
  (bc20/TRAINING_ALGORITHM.md:55-81, bc21/TRAINING_ALGORITHM.md:42-80).
- "The basics, each with its own diagnostic" table: economy (income vs theoretical curve, idle
  resource), nav (rounds to far target, A-B-A oscillation share), exploration (tiles seen by
  round N), symmetry (round identified, false commits), combat (kills per loss vs a scripted
  brawler), bytecode (zero overruns tolerated) (bc20/TRAINING_ALGORITHM.md:83-92).
- Iteration 0 = smallest legal bot, pushed through every instrument to prove the instruments
  (bc20/TRAINING_ALGORITHM.md:94-95).
- Snapshot every accept as a renamed package `src/g_iterN`; `src/bot` byte-identical to the
  incumbent between candidates (bc21/POSTMORTEM.md:241-242).
- Archetypes `src/arch_*`: hand-built opponents that each reproduce one thing the field does.
- Records: append-only TRAINING_LOG with pre-registration + closed-directions ledger with
  re-open conditions; LEARNINGS (each lesson names its measurement); HANDOFF (state + gotchas);
  PROMPTS.md verbatim; progress/ charts regenerated on every accept
  (bc20/TRAINING_ALGORITHM.md:209-223).
- Owner cron: `/loop 30m task check. If the VM is idle and nothing is in the workqueue, start a
  new idea` (bc20/PROMPTS.md:43; bc21/PROMPTS.md "78").

### 1b. 2021 evolution (bc21)
1. Started with a 48-cell fixed panel (opponent x map x side) vs incumbent's record. Rejected 8
   candidates in a row; it could only resolve ~75% effects (bc21/METHOD.md:7-16).
2. Replaced by SPRT mirror: random map + random side per game, batches of 16, H0 p=0.50 vs
   H1 p=0.58, alpha=beta=0.05, LLR bounds +-2.94, cap 240. Next candidate accepted at 68.8%
   (bc21/METHOD.md:18-27). Provisional keep if >=53% over >=200 at cap (bc21/HANDOFF.md:35-39).
3. Owner imposed contest realism (PROMPTS 25-27): external bots only as scrimmages (random map,
   random side, rotating opponents), Elo ladder from our games only, no bot-vs-bot games
   (bc21/TRAINING_ALGORITHM.md:337ff; bc21/PROMPTS.md "25"-"27").
4. "No test before a diagnostic game shows the mechanism firing" became rule (PROMPTS 31) after
   three candidates were inert (bc21/METHOD.md:32-55).
5. Correlation/onset hypothesis generator (owner-driven, PROMPTS 43-56): per-metric
   within-opponent correlation with result, earliest round where it appears and holds
   (bc21/METHOD.md:78-98; bc21/TRAINING_LOG.md:2697).
6. Second arm against an archetype for defence/field-only changes, pre-registered
   (bc21/METHOD.md:156-185); later "neutral in mirror + better on ladder may be accepted"
   (bc21/POSTMORTEM.md:90-94).

### 1c. 2020 evolution (bc20) -- newest, weight highest
1. Started with 2021's SPRT mirror + ladder blocks (bc20/TRAINING_LOG.md:7-50).
2. Ladder rating fixed (PROMPTS 14-17): sequential K=32 Elo with one shared rating was play-order
   dependent (96 calibration games vs unplaced bots lifted us rank 65 -> 4); replaced by batch
   Bradley-Terry fit, each build its own player, band pool of 8 nearest bots either side
   (bc20/LEARNINGS.md:414-419, bc20/TRAINING_ALGORITHM.md:44-53).
3. Fixed engine seed bug found: 491 of 2,825 ladder games were exact repeats; a 240-game gate
   held <=104 distinct games. Engine patched with `-Dbc.game.seed`, every game seeded and
   recorded (bc20/LEARNINGS.md:386-388; bc20/TRAINING_LOG.md:2583).
4. Paired mirror: each cell (map, side, seed) played twice -- candidate vs incumbent AND
   incumbent vs itself. Deterministic engine => concordant wherever the change doesn't fire;
   SPRT on discordant pairs only. Gate 40c read 34-46 REJECT unpaired, but 74/80 pairs were
   concordant and discordant were 4-2 FOR the candidate (bc20/TRAINING_ALGORITHM.md:137-163).
   Cap 320 pairs; sign test p<0.01 with >=12 discordant pairs decides at the cap.
5. Mirror and ladder disagreed in sign (gate g13 REJECT 24-39 while ladder +49)
   (bc20/HANDOFF.md:47-50). Mirror demoted to regression screen; ladder judges field-facing
   changes (bc20/TRAINING_ALGORITHM.md:154-155).
6. League backtest (9 builds x 11 own opponents, 792 games): Spearman 0.85 with ladder but only
   across big gaps; 6 of 11 opponents saturated; only the rush archetypes carried signal
   (bc20/TRAINING_LOG.md:4162-4240). Could not replace the ladder.
7. Replay puppet (owner idea, PROMPTS 59): replays one side of a recorded scrimmage exactly to a
   cutoff, then hands over to our code -- reproduces a field bot's attack without running its
   code. Byte-identical through r2427 on its proof game (bc20/TRAINING_LOG.md:4309-4330;
   bc20/DESIGN.md:241-297). Very elaborate (blockchain tx-order model); it became a harness for
   specific waves, not a gate.
8. Winner's curse found: incumbent's acceptance games rated 1791, its later games 1738
   (bc20/TRAINING_LOG.md:4485). New judge: head-to-head = 3 candidate band blocks (48 games)
   alternating with 3 CONTROL blocks of the incumbent in the same period.
9. Tightened again after calibration (PROMPTS 80): first head-to-head must reach +43 (1 SE),
   confirmed by a second, accept only if pooled 288-a-side lower 1-SE bound > 0
   (bc20/TRAINING_ALGORITHM.md:171-178).
10. Rewrite R1 (PROMPTS 48-49) was what got 2020 unstuck after 7 level iterations
    (bc20/DESIGN.md:84-117; bc20/PROMPTS.md:223 "the rewrite did the trick").

Net trajectory of the gate: fixed panel -> SPRT mirror -> seeded paired mirror -> ladder
head-to-head with same-period controls -> tightened two-stage head-to-head. Each step was forced
by an instrument giving a wrong answer.

## 2. What worked (ranked by evidence)

1. **Copying the tactic that beats you, as your own submission** (owner, bc20/PROMPTS.md:175-183).
   poortho-style rush (second miner plants a production building next to enemy HQ, its units
   bury the HQ) -> gate ACCEPT 60-34 discordant (53-32 at 176 pairs), ladder +79, 53 fast wins vs
   18 -- "the largest gain of the project" (bc20/TRAINING_LOG.md:3258-3300; bc20/DESIGN.md:94-96).
   Enabler: assume the map origin from the corpus (47/47 maps) so the rusher knew symmetry
   guesses from r1 -- plant moved r256 -> r49 (bc20/TRAINING_LOG.md:3262-3268).
2. **Opening deployment** (2021): put the whole starting bank into the best economic unit at r1
   instead of four cheap scouts first. +22 points (71.9%), the first change that carried to the
   ladder (29% -> 40%) (bc21/LEARNINGS.md:91-95; bc21/TRAINING_LOG.md:2847).
3. **Removing binding caps / defects** (2021): guard sink in the spare branch 84.4%, capturer cap +
   two comms bugs 79.2%, slanderer caps 59.1%, "danger = any enemy" halting economy 68.8%
   (bc21/LEARNINGS.md:96-108). "Repairs of own defects and removals of binding caps transfer;
   reallocations mostly do not" (bc21/METHOD.md:149-151).
4. **Comms intake fix** (2021 g_iter11): spawn ORDER on the producer's flag after every build
   meant a busy producer broadcast its map to nobody; captured centres "born deaf". Found by six
   counters on what the centre *hears*; 38/48 ladder, rank 2 (bc21/HANDOFF.md:87-101).
5. **Rewrite on the same infrastructure** (2020 R1): after 7 level iterations, rewrite
   kept Nav/MapState/Comms/HQ/rush; r1s15 +49 on ladder over g_iter12 (bc20/TRAINING_LOG.md:4100-4114).
6. **Cheap defence only under a measured threat** (2021 g_iter13): guards at 15 instead of 20-60
   only when >=3 enemy rushers seen in 50 rounds; rzhan11 42% -> 53%; mirror neutral 57-55,
   ladder 78/96 (bc21/POSTMORTEM.md:47-51, 175-178).
7. **Seat-walk / failure-mode preventer** (2020 g_iter8): every open wall tile gets a unit beside
   it; flood-round deaths 6-7/96 -> 1/96; paired gate 14-0 (bc20/LEARNINGS.md:403-407).
8. **Spend the bank** (2020 Iter 43b): reserves of 300/700 nobody spent -> 200; paired 30-8,
   bodies 200 rounds sooner, banks had ended games at 2,000-12,000 unspent (bc20/LEARNINGS.md:396-401).
9. **Miner never falls through to explore while a resource target stands** (2020 Iter 50):
   target alternation reset the stall counter every turn, miners froze by r300 on 10 maps;
   gate 32-9 (bc20/HANDOFF.md:108).
10. **Rush defence that worked**: under a rush, a far-side production building buys 3 cheap
    flyers at once -- gate vs rush archetype ACCEPT 28-6, mirror 2-2 -> g_iter11
    (bc20/HANDOFF.md:108 "Iteration 58").
11. **Instrumentation that found things**: `@tag k=v` at decision points, grep counts; replay
    dumper `--navstats` refuted a nav rewrite in minutes (bc21/TRAINING_LOG.md:2627);
    `log-scan.sh` makes a block one grep (bc21/POSTMORTEM.md:71-76).

## 3. What did not work / wasted time

### Instruments that misled
- 48-cell fixed panel: 8 straight "no effect" rejects, couldn't resolve <75% (bc21/METHOD.md:9-16).
- Unseeded mirror replaying identical games; unpaired mirror scoring the map/side draw
  (bc20/LEARNINGS.md:386-412).
- Sequential shared-rating Elo: play-order dependent; "nearest above us" pool after a bad block
  re-measured easy bots and lifted rating to rank 1 without information (bc20/TRAINING_LOG.md:208-214).
- Mirror gains not transferring: g_iter7 mirror 64.6% became +2.5 points vs field
  (bc20/TRAINING_LOG.md:2249-2262); 2021 accepts +19/+9 moved ladder by nothing (bc21/METHOD.md:117-122).
- Head-to-head accepts at +-85 noise: +311 claimed, +12 real (bc20/HANDOFF.md:23-26).
- Single fixed-seed diagnostic wins never carried (bc21/HANDOFF.md:82-85; Iterations 52, 60, 62, 63).
- Two chosen diagnostic maps are not a forecast: plateau roles won 2 picked maps by 10-15%,
  lost mirror 42-54, 25-39, 15-33 (bc20/LEARNINGS.md:346-349).
- Analysis-code bugs: CSV header/value misalignment made "coverage" = cumulative moves; caught
  only by an integrity test (coverage in [0,1000]) (bc21/METHOD.md:197-208).

### Strategy lines that burned days
- 2020 enclosure program: 36 stages (a full day) on a copied field design, closed — loses the
  wall race by geometry (16 tiles = half the rate per body) (bc20/DESIGN.md:119-167).
- 2020 citadel (Iter 6), plateau (18-20, plus slot revisions), lattice (17 stages), perch, keep:
  all multi-stage structural programs, all closed level or below (bc20/TRAINING_LOG.md:2883-2975).
  Common failure: copying the *shape* of a top bot's late game without the economy that
  feeds it.
- Correlation-chasing a symptom: rebuilt opponents' unit-size allocation as `arch_big`; it lost
  0-24 to our bot (bc21/METHOD.md:93-98). More scouting raised coverage 50.6% -> 65.9% and won
  nothing (51.7%) — coverage was a marker, not a lever (bc21/TRAINING_LOG.md:2795-2845).
- Rush DEFENCE in 2020: 0 of 5 kept (bury their building, miner freeze, alarm centre, school at
  once, burst rush) (bc20/TRAINING_LOG.md:3275-3300). Defenders at the enemy's building are
  defenders not at home (Iter 53/64). Only the cheap-flyers answer (item 2.10) held.
- Raid/late-drone lines: 5+ attempts, all null on ladder (bc20/TRAINING_LOG.md "Copying tactics").
- "Obviously a bug" fixes that lost: broadcasting a captured centre lost 45.1% because aborted
  capturers became guards (bc21/LEARNINGS.md:109-114).
- Mechanism that paid under poor knowledge stalled under good knowledge (save mode froze economy
  20-187 rounds) (bc21/LEARNINGS.md:128-132).
- Holding fresh captures (floors, sentinels, banks): rejected 15-33 (bc21/POSTMORTEM.md:203-205).
- A cost-aware Dijkstra nav written, then reverted unrun: our units already moved as much as
  the winner; the gap was coverage 46% vs 93% (bc21/METHOD.md:288-292).
- Pre-flood diversions of resource (guns, guards, second producer) consistently priced out:
  "any pre-flood diversion is priced out by the mirror" (bc20/HANDOFF.md:266-267).

### Infrastructure time sinks
- Engine artefacts gone; build needed 3 patches + JDK 8 (bc20/LEARNINGS.md:363-364).
- VM disk filled (replays 4-8 MB each; gates keep every loss) (bc21/HANDOFF.md:142-144).
- Queued jobs that waited on a predicate matching nothing destroyed a 48-game block
  (bc21/HANDOFF.md:151-155); `( while ..; sleep; done; cmd ) &` from a tool call died silently
  (bc20/HANDOFF.md:338-339).
- Reading a running batch: early finishers are the decisive games -> 0-5 mid-read that ended
  11-5 voided a gate (bc21/METHOD.md:274-277).
- Bytecode overrun silently lost 213-404 rounds/game, gated a +10% fix at 53% (bc21/LEARNINGS.md:50-54).
- 2021 games took 15-45 min each (~200/day); 2020 ~1 CPU-min each. Throughput set everything.

## 5. Bot architecture lessons

### Layout (both years, ~1,800 lines)
- `RobotPlayer` -> `Robot` base (turn loop, bytecode monitor, RNG, sensing cache, tryMove/
  tryBuild/flee) -> one controller per unit type; `Nav`, `MapState`, `Comms`, `Debug`, `C`
  (all tunables, each with the measurement that set it) (bc20/DESIGN.md:24-37; bc21/DESIGN.md:27-43).
- Turn loop: record round, `try { turn() } catch`, if round changed -> overrun counter else record
  bytecodes, near-miss at 90%; print `@bc t= used= max= near= over=` every 100 turns
  (bc20/DESIGN.md:221-233). Translate to 2019's per-unit time budget: log ms used per turn and
  per-stage profile (`@bcprof`, bc21/DESIGN.md:87).
- Producer's build logic as a single ordered if/else chain: "the order is the strategy"
  (bc21/DESIGN.md:125-139).
- Static state is per robot; the only shared memory is the comms channel (bc20/DESIGN.md:14-16).
- Keep `Debug` trivial: reflection-ish calls killed every robot at spawn with no message
  (bc21/LEARNINGS.md:9-13).

### Navigation
- Greedy Chebyshev step with Euclidean tie-break + oscillation guard + bug fallback with
  per-robot RNG turn direction; hazard-aware legality check on every step (bc20/DESIGN.md:33;
  bc21/DESIGN.md:107-118).
- Measure before optimising nav: `--navstats` showed moves/unit equal to the winner; the gap was
  exploration coverage (bc21/TRAINING_LOG.md:2627-2660).
- Sticky targets: a target that changes every turn resets stall counters; miners froze
  (bc20/TRAINING_LOG.md:77; HANDOFF.md:108).
- A "nearest X" target must be reachability-filtered and need a stall exit (walked at a cliff
  600 rounds with 5,000 idle) (bc20/LEARNINGS.md:336-338).
- Roles with fixed station lists need a stall exit; diagnose on an edge/corner base too (6 of 16
  units idle all game) (bc20/LEARNINGS.md:303-307).
- Claim races: "nearest free tile" with many units -> re-picks; settle claims once or assign
  deterministically (bc20/LEARNINGS.md:350-353).
- Sector exploration (nearest unseen 8x8 sector, abandoned on stall) took coverage 22.8% ->
  37.5% (bc20/TRAINING_LOG.md:52-90).

### Economy / production
- Every economy decision is made early; in 2020 the HQ could not spawn after r150 and everything
  that mattered was decided by then (bc20/LEARNINGS.md:355-357).
- Producers sharing one bank: the first-acting producer kept spending, the second (acting later)
  never saw its threshold -- starved the school all game on Climb (bc20/TRAINING_LOG.md:1087-1107).
- Never stop the economy for a threat that cannot hurt it (bc21/LEARNINGS.md:96-99).
- Unspent bank is a defect: 2020 ended games with 2,000-12,000 idle; median 0 miners/0
  producers at r1000 with 550+ banked (bc20/TRAINING_LOG.md:4646ff). Track idle resource per
  100 rounds as a standing metric.
- Tiles adjacent to producers are infrastructure: parked units silently blocked spawns
  (bc20/LEARNINGS.md:340-344); a pocket tile boxed by buildings trapped a builder
  (bc20/LEARNINGS.md:315-317).
- Buildings must not cut miners' paths (bc20/TRAINING_LOG.md:2706).
- Deposit only full loads or when local resource is exhausted; a stalled full miner builds a
  drop-off where it stands (g_iter7, bc20/HANDOFF.md:142-144).
- Breakpoints/size tables in pure functions with unit tests (bc21/METHOD.md:250-264).

### Communication
- Shared channel => authenticate: word = hash(payload, round, team salt) (bc20/src/bot/Comms.java:5-35).
- Readers see the channel late / partially: in 2020 each role read one block in three, so a
  message posted once reached a third of units and nobody born later; re-post facts every 10
  rounds, newborns scan back (bc20/LEARNINGS.md:260-263). "Announce three rounds running"
  (bc20/DESIGN.md:96).
- A unit built this round acts next round; orders must persist across the next round
  (bc21/LEARNINGS.md:23-29).
- Every ownership/fact claim carries a timestamp; newer wins (ping-pong of 520 units at a centre
  already ours) (bc21/LEARNINGS.md:123-127).
- Instrument what each unit HEARS, not only what it does; the biggest 2021 fix was found by six
  counters on producer intake (bc21/HANDOFF.md:87-101).
- Robots born somewhere isolated know nothing; whoever learns a map fact posts it, the base
  re-posts it (bc20/LEARNINGS.md:329-330).
- Location encoding `x&127, y&127` decoded nearest the reader (bc21/DESIGN.md:62-64).

### Symmetry / map knowledge
- 3-bit hypothesis set {rotation, mirror-x, mirror-y}, pruned when terrain contradicts an image
  or a predicted enemy base is seen empty (bc21/DESIGN.md:96-105).
- Look at a symmetry guess before gathering around it: raiders rallied 1,500 rounds at the wrong
  image (bc20/LEARNINGS.md:326-328).
- Check corpus regularities (origin always (0,0) in 47/47 maps) -- saved 180-500 rounds of edge
  probing for the rusher (bc20/TRAINING_LOG.md:3262).

### Combat
- Target priority by what the threat carries (shoot carriers of their attack units first)
  (bc20/DESIGN.md:44-46).
- Wave, not trickle: units arriving one at a time into a defended base die one at a time
  (25 built, 3 effective) (bc20/LEARNINGS.md:323-325).
- Know the defender's range and approach only onto tiles outside it; base fires before units act
  (bc20/LEARNINGS.md:332-335).
- Volume beats per-shot efficiency: our 2021 attackers were as efficient per action but acted 3.5x
  less often because of a size-scaled threshold (bc21/TRAINING_LOG.md:4856-4890).
- Area attacks hit friendlies too; bodies near a target dilute (bc21/LEARNINGS.md:59-63).

### Determinism / symmetry of play
- No `Math.random`; per-robot LCG from id (bc20/DESIGN.md:19).
- Sensing returns row-major order; pick best, never first; tie-breaks relative to own geometry,
  never fixed compass order (bc21/DESIGN.md:22-25).
- Mirror harness exposes play-symmetry bugs: lopsided results under identical code = a bug
  (bc21/TRAINING_ALGORITHM.md:66-74).

### Compute budget
- `java.util` counted as own code -> arrays, unrolled loops; scans over tiles x memory overran
  (sample them) (bc20/TRAINING_LOG.md:72-78).
- Periodic tasks coinciding on one turn caused overruns: stagger them (bc20/TRAINING_LOG.md:83).
- A producer over budget silently skips build and bid; check `over=` for every unit type before
  trusting any gate (bc21/METHOD.md:283-285).

## 6. Process mistakes and owner corrections

Agent mistakes (self-recorded):
- Read a forbidden (locked-tier) bot's replays without checking the tier; disclosed; made the
  rule mechanical (replay-dump refuses) (bc21/TRAINING_LOG.md:3803-3845). Lesson: rules enforced
  by "remember to check" fail silently -- encode them in tools.
- Wrote a false excuse into METHOD ("mirror undervalues changes both sides get") for a day;
  the owner caught it (bc21/PROMPTS "62"; bc21/TRAINING_LOG.md:2795).
- Reinterpreting nulls after the fact; reading partial batches; trusting single seeds.
- Accepted on point estimates inside +-85 noise six times (bc20/TRAINING_LOG.md:4676).
- `git checkout` cannot undo a committed change to `src/bot`; restore from snapshot
  (bc21/HANDOFF.md:37-39).
- `str.replace` silently matching nothing left code unchanged for a whole iteration; use
  `assert old in s` (bc21/HANDOFF.md:166-167).
- Two finished blocks never posted until shutdown (bc20/TRAINING_LOG.md "Housekeeping").
- Stale docs: ELO.md contradicted a stated rank (bc20/PROMPTS.md:95-99) -- owner reads the repo.

Owner corrections / directives (all binding style):
- Use the big VM, never the driver, for games (bc21/PROMPTS "9"); document setup.
- External bots only as scrimmages: random map + side; no external-vs-external games; ladder
  from our games (bc21 PROMPTS 25-27).
- No gating against external bots ("you can't scrimmage without submitting") but mine every
  scrimmage for the next hypothesis (bc21 PROMPTS 37-38).
- Diagnostic before test, encode it in TRAINING_ALGORITHM (bc21 PROMPTS 31).

## 7. Lessons for 2019 (castles/churches/pilgrims/3 combat types, costly radio, time budget)

Opening and economy
- Opening deployment dominated 2021 (+22 points, the first ladder-moving change). Spend the
  start bank on the highest-return economic unit immediately; audit rounds 1-20 move by move
  against a strong replay before tuning anything later.
- Find the binding cap before tuning (2021: three accepts were cap removals). Put caps in `C`
  with invariant tests.
- Two producers share one bank (castles + churches): define spending priority explicitly or
  the first-acting producer starves the other (bc20 Climb finding). Log per-producer
  "wanted to build, could not" counters.
- Track idle resources per 100 rounds and production actions per 100 rounds from day 1; an
  unspent bank was the persistent 2020 defect.
- Drop-off placement: 2020 accepted "a stalled full miner builds a drop-off where it stands" and
  "deposit only full loads"; church placement next to resource clusters is the analogue. Keep
  depots off miners' paths and keep spawn tiles of producers free.
- Pilgrims carrying two resources: sticky targets, reachability filter, stall exit, never fall
  through to explore while a target stands (2020 Iter 50 fixed frozen miners on 10 maps).

Rush, defence, turtle vs aggression
- The biggest 2020 gain was a rush copied from the field; rush defence was the hardest problem
  (0/5 kept). Build a rush archetype early, before you need it, and gate defence against it
  (paired, `OPP=arch_rush`) plus a no-regression plain mirror.
- Defence that held: cheap units bought only when a threat is measured (2021 swarm rule; 2020
  far-side producer buying 3 cheap flyers). Defence that failed: sending defenders to the
  enemy's forward building; standing defences bought pre-emptively (priced out).
- Per-map adaptivity from measured signals (base distance, resource density), not compile-time
  (bc20/RESEARCH.md:46-47).
- Turtling costs: every pre-threat diversion (guns, guards) was priced out in 2020's mirror;
  survival bought with inactivity is a ledger regularity (bc20/TRAINING_ALGORITHM.md:238-240).
  But a rush only pays early: 2020's rush "worth nothing late and costs a miner"; added a
  give-up timer.
- Wave not trickle for attacks into a defended base; respect the defender's range and that
  structures act first.
- Long-range unit with a minimum range and an area-damage unit: unit-test the target
  selection geometry; area damage dilutes/hits friendlies (2021 speech splitting).

Communication (radio costs fuel)
- 2020's channel cost resource and was shared/late: messages reached a fraction of readers; the
  fix was periodic re-posts plus newborn back-scan. With costly radio, design what must reach
  newborns (base location, symmetry, targets) and budget re-broadcast deliberately; measure
  fuel spent on radio as a metric.
- Timestamps on every claim; orders persist across the newborn's first turn; instrument what
  units hear. An order broadcast after every build can mask everything else on the channel
  (2021 "born deaf").
- Authenticate or otherwise guard against misreading enemy signals if the channel is shared.

Symmetry and map
- Implement symmetry hypothesis pruning in phase 0 with a unit test; verify a guess by sight
  before rallying around it. Check the map corpus for regularities (sizes, symmetry types,
  base placements) with a mapinfo tool.

Compute (per-unit time budget, not bytecode)
- Monitor from line 1: per-turn time used, near-miss, overrun, per stage for producers. A
  producer that overruns silently loses builds and invalidates every gate.
- Stagger periodic tasks; sample scans; avoid allocation in hot paths.

Method (port from day one)
- Build: runner (parallel, seeded, recorded seed), replay dumper with navstats/per-round CSV,
  `@tag` logging, unit tests, SPRT, paired mirror, scrim band ladder with batch BT fit, onset/
  correlate, field-score chart. Verify engine determinism and seed control before any gate.
- Diagnostic game showing the counter fire before any test; diagnose on a map where it can
  fire AND one where it can't; run 10 random maps counting deaths/role churn before a gate.
- Mirror = regression screen; ladder (same-period control blocks, >=1 SE, confirmed) = judge for
  field-facing changes. Pre-register which instrument decides. Never reinterpret a null.
- Copy what beats you as its own submission; keep one archetype per field behaviour, and run
  each archetype on a known case before trusting it.
- After 3 rejects in one functional area, switch area or do a structural attempt; when flat for
  ~5 accepts, ablate, sweep API, re-read games, then rewrite on the same infrastructure.
- Avoid multi-day structural programs that copy a top bot's late-game shape without its
  economy (2020 enclosure/plateau/lattice: ~3 days, nothing kept). Give each a stage budget and
  a closing criterion up front.
- Games against external bots only as random scrimmages; never read their source; replays of
  any game may be reviewed (2020 rule).
- Ops: VM for volume; private build trees per concurrent run; prune VM disk after each block;
  never read partial batches; wait on result files not process names; `pgrep` bracket trick;
  push after every commit; record PROMPTS verbatim; keep docs current because the owner reads
  GitHub.
