## 1. Training method

### 1.1 Instruments (TRAINING_ALGORITHM.md:14-24)
- **Mirror gate**: candidate vs incumbent snapshot, random map/side, one fresh engine seed per cell **shared by both
  builds**. Each cell is also played incumbent-vs-incumbent on that seed (paired). Only discordant pairs count.
  Tool: `tools/paired.sh` (header lines 2-14), `tools/mirror.sh`.
- **Sparring archetypes**: our own one-trick bots that copy a field tactic (arch_rush10, g1escrg convoy, g1drift80).
  Owner PROMPTS 6 (PROMPTS.md:47): "If self-play can't show the value of a rush defence ... implement a rush offense".
- **Ladder**: scrimmage blocks vs external bots under contest rules (random map, random side, fresh seed, rotating
  opponents). Batch Bradley-Terry fit on the Elo scale. Each of our builds is its own player.
- **Replay reader**: one game as text (TRAINING_ALGORITHM.md:21).
- Rule: run every instrument first on a case with a known answer. A mirror result never judges a field-facing change
  (TRAINING_ALGORITHM.md:23-24).

### 1.2 Phase 0 checklist, day one (TRAINING_ALGORITHM.md:26-42)
Rules digest with engine provenance; headless bare-JVM runner; per-game seed; timeouts; dud/exception detection;
private class trees per run; determinism check; replay reader + tests on synthetic replays; bot iteration 0 with a
bytecode monitor, per-robot RNG, a tie-break helper, log tags, constants file, unit tests; snapshot tool; external
field discovered, compiled blind and calibrated; charts + handoff regenerated by one post-block command; **identity
control** (byte-identical copy reads 0 discordant) on every verdict tool path; **basics battery**.

### 1.3 The loop and acceptance funnel (TRAINING_ALGORITHM.md:44-68)
1. Select a target from the rotation (§1.5). 2. Trace the motivating replay; check a second game vs another opponent.
3. **Pre-register**: mechanism, firing counter (log tag), reachability at observed values, trigger frequency, price,
   deciding instrument, gate, falsifier, dose ladder with a byte-identical zero arm.
4. Implement one change behind a switch (`C.java`). Tests pass, including the dead-code and arm-intent checks.
5. **Diagnose, no shortcuts** (owner PROMPTS 66-67):
   (a) one logged game, read against the incumbent on the same seed;
   (b) **delivery mini-block** (`tools/delivery-gate.sh`, ~24 random band cells): the mechanism fires in >= 90% of games
       and its signature reaches its target (for a copied tactic, >= 50% of the gap). `tools/band-test.sh` **refuses
       without the PASS file** (band-test.sh header). Verdicts are three-way: PASS = 1 SE beyond the bar, FAIL = 2 SE
       short, otherwise INCONCLUSIVE, auto-extended 24 -> 48 -> 96 (-> 192) cells (HANDOFF.md:207-212).
6. Gate. 7. On accept: snapshot, ladder blocks, post-block, docs, commit, push.
8. On reject: restore `src/bot` byte-for-byte from the snapshot; log the closing number and a re-open condition.
- Delivery check syntax: `median:crumbs200>=2500 mean:traps200<=6 fire:digs200>0>=0.9 rel:X>=1.2 nw:Y<=1.1` (delivery-gate.sh
  header). `nw:` = "not worse" guard, failing only beyond 2 SE. The **kills guard was removed** by the owner (PROMPTS 183).

### 1.4 Statistics and sample sizes
- **Early regime (09-30 to 10-02)**: mirror SPRT on discordant pairs (H0 0.50, H1 0.58, alpha = beta = 0.05, batches
  of 16, cap 320 pairs; TRAINING_ALGORITHM.md:94-98, 148-150). Field judge = 110-game full-field blocks. It was useless:
  every arm landed within +-4 of 84/110 (TRAINING_LOG.md:191-197; LEARNINGS.md:59-60).
- **Band test (from 10-01)**: 20 bots rated nearest the incumbent (`tools/elo.py --band 20`), 120 games per seed,
  2 seeds = 240 pairs on identical cells (TRAINING_LOG.md:191-197; band-test.sh).
- **Noise floor**: at 234 band pairs, 1 SE is about 6.5 net games, or about 20 Elo. Only ~40+ Elo effects were visible
  (LEARNINGS.md:53-56; TRAINING_LOG.md:810-815). Arms that change behaviour disagree with control on 14-38% of seeded
  pairs (MEAS2). Size blocks from measured discordance.
- **Per-pair metric**: wins carry 2.2-5.6x less information than the **capture difference** (our objective units minus
  theirs, per game) (LEARNINGS.md:58-66; criteria-review verdict.md:26-40).
- **Final shipping rule** (owner PROMPTS 186-188; research/REWRITE_EVAL.md:35-50): t_all = all-cell capture-diff delta/SE,
  t_up = same on the upper tier. Ship if (t_all >= 2.3 or t_up >= 2.6) and wins net >= 0. Sequential looks:
  look 1 = 240 pairs (ship if t_all >= 3.0; stop if t_all < 0.5 and t_up < 0.8); look 2 = 480; look 3 = 720.
  Simulated: null arm ships 2.0%; a +30 Elo arm ships 63-65% (the old rule: 17% as written).
- **Elo conversion**: ~12-13 Elo per band win point (verdict.md:62-63).
- **Ladder fit**: batch Bradley-Terry, weak prior, repeated (pair, map, seed) cells counted once. **Cap of 200 games per
  pair** (PROMPTS 191). Without the cap, 1,500 filler games vs one 30% matchup pulled g_iter7 from 2150 to 2116
  (LEARNINGS.md:98-103). Fit had a convergence bug: ratings 30-44 points low (MEAS11).
- Never read a running batch. Never move a bar after seeing a number. Read the shape of diffs (one map/side = real;
  scattered = noise) (TRAINING_ALGORITHM.md:119-121).

### 1.5 Candidate generation (TRAINING_ALGORITHM.md:70-90)
- Rotation: (1) defects in our own games; (2) tactics the field beats us with (TACTICS.md, "Adoption" then
  "Neutralization"; owner wording PROMPTS 21); (3) block census: the earliest metric that separates wins from losses;
  (4) capability gap (unused API, mechanics); (5) tactic levels (TL-1).
- Balance: 3 consecutive rejects in one area -> leave it. >= 1 structural swing per 4 attempts.
- **Plateau escalation order**: correctness audit FIRST, then ablate, API/engine sweep, re-read field games, re-read
  ADVICE, jointly necessary pairs, structural attempt, rewrite.
- **Ladder target** (owner PROMPTS 120, 157-159, 177): one opponent at a time, usually the bot just above us. Goal:
  "a single, unambiguous victory over a higher-ranked opponent ... find a little crack to widen". Pre-register the
  victory read (e.g. >= 60% of >= 120 scrims + paired net >= +2 SE; TRAINING_LOG.md:862-867).
- **Two-group contrast study** (the best single lever finder): compare a behaviour rate between the bots that beat us
  and the bots we beat. A trait where we differ from the first group and match the second is a candidate
  (LEARNINGS.md:175-183).
- **Mine our own coin-flip tie-breaks** as randomized experiments for causal effects of a decision (LEARNINGS.md:288-294).
- **Stacking near-misses** (owner PROMPTS 180, 187): parts must each have delivered, have positive band estimates and
  independent mechanisms. The stack is tested as a new arm (TRAINING_ALGORITHM.md:108-116).

### 1.6 Compute, ladder and replicas
- Session machine (2 vCPU) plays one diagnostic game at a time; a GCE e2-standard-8 VM plays games in volume
  (CLAUDE.md:259-260). The first zone had no capacity; they moved zones (LEARNINGS.md:338-340).
- **Standing queue** `tools/vm-queue.sh` (flock, one runner) plus an **idle filler** job. The VM had been idle 29% of
  uptime between runs (LEARNINGS.md:306-310). Fillers became 80% of ladder games and distorted the fit until the
  pair cap (LEARNINGS.md:148-153).
- External bots: GitHub search (694 rows -> 462 repos cloned -> 73 using the 2024 API). Sparse checkout outside the
  repo. Classified by counting API names, never displaying content. Compiled blind with counts to stdout
  (BENCHMARK.md:159-184; tools/bench-compile.sh). `tools/bench-select.py` picks each repo's final bot **by package
  name only** (final > postqual > quals > seeding > highest version).
- Diagnostics may choose map and side vs external bots (PROMPTS 178), via `tools/diag-batch.sh`. Those games never
  enter the ladder.

## 2. What worked, ranked by impact

1. **Correctness audit of bot AND measurement tools** (+185 Elo directly; +77 more from levers it found).
   - 10-02 audit: 5 lenses, 2 adversarial verifiers, 8 agents, 4.2 h, 1.78M tokens. 41/42 findings confirmed
     (AUDIT_PLAYBOOK.md:5-14).
   - Fixes combined in g1basics: +33 net over 234 seeded band pairs (p < 0.001); +29 on confirmation seeds -> g_iter2,
     1652 -> 1821 (LEARNINGS.md:234-245; progress/REWRITE.md g1basics rows).
   - Bugs found: own-flag alert fresh in 1057-1686 of 1800 rounds, which switched off every defender (A1). Robots froze
     on enemies behind walls (A4). Flag registry stale up to 1393 rounds (A5/A6). Symmetry wrong on 32% of map-sides
     (A3). Enemy flag ids encode the enemy spawn exactly and were never decoded (A2). Unseeded pairs (B2).
     (research/AUDIT-2026-10-02.md summary table.)
   - Second audit (10-03, 56/56 reproduced) fed g_iter4 (BOT1: captured own flags never recognised), g_iter5 and
     g_iter6.
2. **Two-group contrast study -> heal hold** (+144 Elo in one step; t_all 6.46 at look 1). With an enemy within dist2 10
   we healed 0.445 of the time vs the upper tier's 0.257, and held a ready strike 0.196 vs 0.318. Against the rest the
   rates were near parity. Fix: keep the action for a strike when an enemy is close (LEARNINGS.md:175-183; TACTICS T16).
3. **Seeded paired cells + identity control** on the exact verdict path. Before the fix, ~2.5 days of tallies were
   mostly noise (LEARNINGS.md:46-51).
4. **Slowing an unstoppable opponent mechanism** (the waffle crack, +55). Denying re-grabs was physically infeasible.
   Carrier stuns + flag relocation away from its spawn went 146-94 and were band-positive -> g_iter3 (LEARNINGS.md:167-173).
5. **Defensive objective placement by greedy climb** over visible reachable tiles, not a precomputed spot (23% of
   precomputed spots were unreachable). +26 Elo, g_iter6 (LEARNINGS.md:211-216).
6. **Stacking two positive near-misses** with independent mechanisms (centre crumbs + pick-after-move): t_all 3.25 at
   720 pairs -> g_iter5, +51 (LEARNINGS.md:141-146).
7. **The day-1 stack** (symmetry hint, trap rings, advance, float spending, carrier chase): +246 Elo on the ladder, ACCEPT
   27-1 discordant in the mirror. It fixed a self-play standoff: mirror games all went to r2000 with 13k crumbs floating
   (TRAINING_LOG.md:35-56).
8. **Tool-enforced delivery gate**. It stopped z1hold, b2dig5, g1icpt, g1esc2, b2rgc, g2rgh, g4contact8, g7fc and g7ring
   before a 240-game band test (LEARNINGS.md:122-128).
9. **Paired 5(a) blocks on chosen cells with exact twins**. Centre crumbs won 7 cells to 1 on the relevant map class,
   after a critic had demoted the lever (LEARNINGS.md:280-283).

## 3. What did not work / wasted time

- **~80 tactic arms on a broken base** (09-30 to 10-02): none accepted (LEARNINGS.md:427). Root causes:
  unseeded noise, broken basics, an underpowered metric (wins), and arms never checked for delivery.
- **Stacking on non-inferiority**: bases B1-B3 each "not worse". The paired filler later showed B1 at -30 over 1,870
  pairs (-1.8 SE). The stack drifted below the incumbent (LEARNINGS.md:135-139).
- **Proxies that deliver but do not convert** (LEARNINGS.md:254-264):
  - re-grabs +9.1 SE, but the arm went 11-26 (each extra re-grab ended in a dead carrier);
  - levels +16.5 SE, net -13;
  - stillness -4 points, 11-24;
  - saving robots (deaths -12%, step-ins down 99%) moved captures not at all (S8, LEARNINGS.md:218-223).
- **Offensive presence arms** (grabs, relays, escorts, dives, convoys, late all-ins) failed again and again. "Presence
  at enemy flags is an outcome of winning the fight, not a lever" (LEARNINGS.md:203-209).
- **Economy/level arms**: 8 tried, 0 shipped. Five stopped at 5(a). A design projected +22 levels and delivered +7
  (LEARNINGS.md:185-193).
- **Copying "beaters have more X" correlations**: aggression, retreat threshold, specialisation, cohesion, smooth-score
  micro (1-25!), and hold-the-line all failed. The attack/heal gap was "a symptom, not a knob" (TRAINING_LOG.md:174-189;
  ledger TRAINING_LOG.md:366-388).
- **8-agent rewrite design** ("architecture ceiling") launched before checking the basics. Its consumer was never
  built, and 528 dead lines were left behind (F1, LEARNINGS.md:378-384).
- **Target-specific gains**: g7ehp was +28 over 240 pairs vs andli28 (+3.3 SE) but band-neutral. ~25 arms vs two
  targets cracked neither; both fell to band-wide promotions (LEARNINGS.md:157-165).
- **Re-testing closed arms wholesale** on the fixed base: 8 tried, 0 delivered (LEARNINGS.md:296-302).
- **Ablating features whose code path never ran** (dam/float traps, bank < threshold on 64/75 maps): void (A8,
  LEARNINGS.md:247-252).
- **17 filler blocks (~2,000 games) played and never recorded** until the owner asked (LEARNINGS.md:130-133).
- **Disk full twice** from replays. A queue logged "exit 0" for failing jobs ($? held a date substitution's status)
  (LEARNINGS.md:320-326).
- **Building a study's ranked levers before chasing its top open question** (vertical-symmetry penalty, z -2.9): four
  levers built, none shipped, and the question was never answered (F4, LEARNINGS.md:396-403).
- Day-one self-imposed ban on choosing maps in diagnostics, carried 4 days and never raised with the owner
  (LEARNINGS.md:355-359).

## 5. Bot architecture lessons

### 5.1 Structure (src/g_iter7, ~3k lines; TRAINING_LOG.md:20-25)
- `RobotPlayer` (39 lines): turn loop. Overrun = round number changed during the turn. Near miss = > 90% of limit.
  Both exception types are caught and counted. `Clock.yield()` at the end (src/g_iter7/RobotPlayer.java:11-37).
- `G`: per-robot globals. xorshift RNG seeded from the robot id ("identical code on both sides never shares a
  sequence"). `nearest()` breaks ties by the robot's RNG, never by array order. `testBc` hook, because Clock reads 0
  outside the engine (G.java:19-21, 74-100).
- `C`: every constant and switch, with a comment giving its provenance (C.java). Arms flip switches; with defaults
  `src/bot` plays exactly as the frozen incumbent.
- `Comms`: 64-slot schema documented in a header, one purpose per slot, locations encoded x*64+y+1 with 0 = none
  (Comms.java:5-50). Slot-layout unit test.
- `Nav` (115 lines): greedy step, then bug-follow with per-robot handedness (id parity) until strictly closer. Stall exit
  after 20 turns without progress flips handedness. Fill water when stuck (Nav.java:5-70).
- `Micro`: kite and strike on the threat radius. Target order: carriers, then lowest HP, then highest attack level.
- `Sym`: symmetry candidates as a bitmask, never emptied, decided by observation (below).
- `Duck`: role logic, 1,242 lines: setup, then the main phase.

### 5.2 Navigation
- Audit A7: Nav reset bug state whenever the target moved, so chasers could never get round a wall. Fix: reset only when
  the target moves > dist2 8 (Nav.java:22-27). ADVICE §7 says the same: "the stall counter must survive target flicker".
- A9: bug-follow ping-ponged at the map edge (fix: flip handedness once per call).
- BOT8: after a fill, step onto the tile in the same turn (~90 lost steps a game).
- A4: any visible enemy took the whole turn, even behind a wall: 16-36% of enemy-in-view robot-rounds frozen. Fix: an
  enemy takes the turn only if within dist2 8 or reachable in 3 moves, with a bytecode-gated BFS (C.REACH_FIX, REACH_BC).
- Cutting setup fills to save resources broke navigation over water. Arrival was ~40 rounds later and fights got worse
  (TRAINING_LOG.md:395-406). "Infrastructure is not waste."

### 5.3 Symmetry and hidden-state inference (the trigger of the whole turnaround)
- g_iter1 narrowed candidates with round 1-3 hints, then **guessed** ROT > FX > FY. A terrain check existed but had no
  caller. Wrong on 32% of map-sides (TRAINING_LOG.md:907-1000).
- Owner bar: "You should be able to determine symmetry 100% accurately after a limited number of observations. If you
  can't then that's a bug" (AUDIT_PLAYBOOK.md:57-60).
- The repair (Sym.java:5-23):
  - geometry at start (the image of our spawn cannot fall in our own spawn zone);
  - the image of our spawn must be THEIR spawn tile;
  - per-robot bitset memory of immutable tiles (walls, spawn zones, the setup-phase dam): a tile seen now must match
    its remembered image;
  - AND-merged through one shared slot;
  - equivalent candidates collapse;
  - **scouts** walk to the nearest distinguishing tile while undecided;
  - each tile processed once (not every turn);
  - runs after the turn, only with >= 6000 bytecodes left, and stops at 2500.
- SymTest: 300 random symmetric maps with simulated vision. The truth is never eliminated; decided within 13 disks.
- Remaining audit gaps: while undecided, consumers should get **every live candidate**, not a guess (BOT15). Exact
  evidence the engine gives away (ids that encode spawn index) must be decoded (A2).
- The repair alone was neutral (63-57) because the bot barely consumed symmetry. It was still the foundation for
  anything destination-based. ADVICE §8: "Name the decision that will use a fact before building the sensor."
- Map-class effects confound "we lose when the inference is wrong" (LEARNINGS.md:92-96).

### 5.4 Economy
- "The economic lever that worked took free resources without taking actions or crumbs from fights"
  (LEARNINGS.md:185-193). Banking, budgets and level farms all failed or starved.
- Break an economic gap down by source before building. Vs the upper tier the gap was the **kill reward on enemy
  territory**, not the map's resources: 66% of our deaths fell on our side (LEARNINGS.md:225-230).
- Firing census first: dam traps needed a bank of 700 that existed on 11/75 maps. The float threshold was reached in
  0/235 games (LEARNINGS.md:247-252).
- A self-play standoff with 13k resources floating by r1500 was the day-1 defect; spending the float fixed it.

### 5.5 Comms / shared state (audit lens 3; ADVICE §9)
- An alert defined as "any enemy seen near the flag" was on almost all game. Alerts must encode a real threat with an
  explicit clearing condition seen firing in long games (A1).
- Registry entries must expire when their tracker dies ("carried by us" stayed forever, A5). A dropped flag's last tile
  outlived its return home (A6).
- A captured own flag was never recognised: defenders guarded an empty home in 82% of games vs one opponent (BOT1, +16 Elo).
- A carrier sighting expired after 5 rounds, though a simple predictor stays within 2-4 tiles for 50 rounds (BOT10).
- Write-only slots and counters were a frequent audit finding. Make each slot's documented meaning a replay assertion.

### 5.6 Combat micro
- Kite-and-strike with separate move/action cooldowns: hit, step out of reach; when ready, step in and hit
  (Micro.java:5-9).
- **Biggest micro win: tempo.** Hold the action for a strike with an enemy close instead of healing (+144 Elo).
- Saving robots (kite out below 700 HP, step-in discipline) delivered huge proxy deltas (+17.9 SE) but no captures.
  "Some deaths are the price of defending."
- Refuted: smooth tile-scoring micro v2 (1-25, 1-26), cohesion (4-18), retreat threshold (monotone worse above 300 HP),
  aggression margin (no dose response).
- 2024 load-bearing: buy the ATTACK upgrade first (capture-first went 14-33); HEALING at r1200 (S5, LEARNINGS.md:195-201).

### 5.7 Bytecode / time budgeting (LEARNINGS.md:112-118; ADVICE §3)
- Treat headroom as a basic. 0 overruns is a bar; any overrun voids a candidate (it is not a reject).
- Observed symmetry + reachability BFS took the peak to 24.7k/25k and caused 1 overrun in 234 games. A cheaper BFS
  (REACH_FAST) gave identical play at a 23.0k peak.
- **A feature that spends spare bytecode on purpose hides real near misses.** Sym.update filled turns up to the 2500
  guard, so maxBc saturated and a real 23.6k (95%) relocation scan hid among them (BOT16, MEAS7). Measure near misses
  excluding opportunistic fill work.
- The first turn is the most expensive: a 27x27 adjacency loop cost ~18k of 25k on round 1. Replaced by a bitset
  (G.java:37-49). Nested-loop membership tests cost ~35k; bitsets made them O(1).
- Bytecode-gated optional work: `if (bcLeft() > X)` before searches; loops stop at a floor.

### 5.8 Objective / defence (2024-specific but transferable)
- Static fixed-spot defence (more defenders, a wider alert, a fortress, a stun on the flag tile) was refuted. Moving
  objectives away from the enemy's approach by an observed climb worked.
- Against a re-grab relay you cannot deny: slow it (stuns on carriers) plus distance.

## 7. Year-agnostic principles distilled

1. **Build the measurement before the first arm**: seeded paired cells; an identity control reading 0 discordant on
   every verdict path; three-way verdicts; a shipping rule on the most informative per-pair number with simulated
   power; a pair-capped batch BT ladder; filler budgeted by information (LEARNINGS.md:464-466).
2. **Audit before building arms**, and again at every plateau: 5 read-only lenses (dead code, rules/API, shared state,
   behaviour in replays, measurement pipeline) + hidden-state beliefs + budgets/extremes, adversarial verifiers, then
   measurement fixes first, each bot fix behind a switch, one combined build, confirmation seeds
   (AUDIT_PROMPT.md; AUDIT_PLAYBOOK.md).
3. **A plateau means broken basics until proven otherwise**, not an architecture ceiling. One broken basic is a sample
   of a class.
4. **Anything knowable exactly after bounded observations must never be guessed.** Compute the achievable bound
   offline over every map and side and set the bar from it. While undecided, act on all candidates.
5. **No statistical test before delivery**: a diagnostic game shows the mechanism firing, then a 24-cell block shows the
   signature moved. Enforce with a tool that refuses.
6. **Every rule must be enforced by a tool**; prose rules are followed in letter only.
7. **Judge on the objective-difference metric, not wins**. Wins on foregone cells carry no signal. Test on the band of
   bots near your rating, split upper/rest.
8. **First looks regress toward zero**; let pre-registered sequential looks decide. Never close a line on INCONCLUSIVE.
9. **Estimate the proxy-to-outcome link before building**. Delivered proxies (re-grabs, levels, saved units) often do not
   convert. Pair a signature bar with an outcome guard.
10. **Price fixes on identical cells, never from correlational splits** (defects cluster on hard maps).
11. **Measure firing frequency of every code path** before tuning or ablating it; ablating a never-firing feature is void.
12. **Verify inertness mechanically**: refactors claimed equivalent must read 0 discordant; check switch intent in the
    built source; show every check failing on a known-bad input.
13. **Find levers by two-group contrast** (beaters vs beaten) of behaviour rates. Mine your own random tie-breaks as
    randomized experiments.
14. **Copy what the field does, but not "they have more X" symptoms**. Tempo and discipline differences transfer; volume
    knobs do not.
15. **Ship on the band; use targets as diagnostics**. Target-only gains rarely climb. Slice target games by map symmetry
    and side on day one.
16. **Stack only components that each delivered and read positive**, with independent mechanisms; test the stack as a
    new arm. Never stack on "not worse".
17. **Key every result by (code hash, opponent, map, side, seed)**. Retention keyed to consumers. Disk checks. Jobs fail
    loudly. Lock shared test dirs.
18. **Compute is lost between runs**: standing queue + idle filler, collected automatically every task check.
19. **0 overruns, and keep the near-miss detector able to see** (exclude opportunistic fill work). First-turn cost and
    nested loops are the usual offenders; use bitsets.
20. **Owner questions are cheap audits**: answer from the code and data, turn each correction into a tool rule, keep the
    front page and a single generated state file current in the same commit as a promotion.
21. **Never idle**: while a gate runs, read replays and prepare the next candidate (TRAINING_ALGORITHM.md:90).
22. **Engine setup**: build from source if artefacts 404/403, patch in a seed property, verify determinism (same seed
    identical, different seed different), and find unseeded randomness in the engine and the example bot.
