## 1. Training method

### 1.1 The instrument hierarchy (TA:7-23)
- Objective: absolute strength against the external field. Beating our own earlier builds only counts as a means (TA:9-10).
- Six instruments, each with a stated blind spot (TA:14-21): the rules digest, the replay reader plus the bot's own counters,
  the mirror (paired seeded cells against the incumbent), sparring archetypes, the external ladder replica, and a
  frozen roster of snapshots.
- When two instruments disagree, run a third and report the disagreement. Never pick the convenient one (TA:23).

### 1.2 Phase 0 before any tuning (TA:25-53)
- Required before the loop: a rules digest with engine locations; a headless parallel runner keyed by (code hash,
  opponent, map, side, seed); a **determinism check** and an **identity control** (a byte-identical copy must show 0
  discordant pairs); a replay reader with fixture tests; a layered bot with an overrun and exception monitor from the
  first commit; the external field; the ladder replica and views; and a basics battery (TA:29-50).
- Foundation bar: the bot beats the starter bot from both sides on every map, passes basics, and is on the ladder. Then
  run a correctness audit, then start the loop (TA:52-53).
- In practice: the foundation bot g_iter0 was done on day 1. It went 206/206 against examplefuncsplayer on all 103 maps
  from both sides, with 0 overruns, 0 exceptions and symmetry never wrong (TL:46-60). First field calibration
  (174 games): 75.3%, BT rank 17 of 88 (TL:62-70).
- The day-1 replay trace found first-turn overruns, carriers mining 0 mana, and 1-7 exceptions a game from shared-array
  writes after moving (TL:48-52). That is a basics checklist worth repeating.

### 1.3 The acceptance funnel as it ended up (progress/ATTEMPTS.md:6-13; LS:140-184)
1. **Local head-to-head (h2h)**: every map x both sides (206 games) against the incumbent. "Signal" = maps won on both sides
   minus maps lost on both sides. It switched from map seeds to explicit random seeds once map-seed games turned out to
   be deterministic replays (LRN:68-73).
2. **Pre-trial screen** (`tools/screen.py`, about 1.5 h on the VM; LS:159-184):
   - (a) basics: 8 games against the starter bot, must be 8/8 with 0 overruns, exceptions, self-deaths or symmetry errors;
   - (b) 20-game h2h against the validated build on the 10 panel maps: PASS at 11 or more, BORDERLINE at 9-10.5, FAIL below 9;
   - (c) the archetype roster, 20 games per archetype, paired with the incumbent's cached games. It can block,
     never accept, and gates only with a VALID fidelity record. None ever got one, so it was information only (HO:281-287);
   - (d) basics over every game.
   - `trial-start` refuses without a PASS record for that code hash (LS:52-54). `--skip-screen "<reason>"` overrides it
     and logs the reason; it was used for basics fixes and parameter stacks.
3. **Panel trial on the replica**: 100 unranked games (10 field bots x 10 maps), paired cell by cell against the
   validated build's own panel run. Net = gained - lost; most cells are identical (LS:26-29).
4. **Decision rule**, made formal on 2026-10-20 (LS:140-157), with D = discordant cells and t = net/sqrt(D):
   - block 1: accept at t >= 1.5 with net >= +3, reject at net <= 0, otherwise play block 2 (the same cells with sides swapped);
   - after block 2, accept at cumulative t >= 1.5 with net >= +3;
   - simulated P(accept) at a true per-block net of -3/0/+3/+5: 0.01/0.11/0.46/0.76 (LS:149-152);
   - basics exception: a fix that removes a basics failure may be accepted at block-1 net >= 0 (LS:153-154).
   - Before this rule the habit was "accept at net +1..+3 on one panel", which accepted about 44% of null candidates
     (TL:2591-2600; LRN:151-156).

### 1.4 Statistics (TA:111-121, TA:169-181)
- The unit of evidence is the paired cell (opponent, map, side, seed). Only discordant pairs inform. Coin-flip
  tiebreak games are excluded (`tools/paired.py` docstring).
- Never read a running batch, never move a bar after seeing a number, never reinterpret a null. A fixed-seed single
  game is a filter, never a verdict (TA:114-116).
- Compare against controls from the same period on the same pool (TA:116). One reference panel is one draw, so judge
  against two (TL:918-933; LRN:77-82).
- Simulate a gate's power before relying on it: "a gate that cannot pass a real gain is a defect" (TA:120-121).
- Defaults: delivery mini-block of 24 paired cells, extended to 48/96/192; mirror SPRT p0 0.50, p1 0.58, alpha =
  beta = 0.05; BT pair cap of 200; 3 rejects before leaving an area; at least 1 structural attempt in every 4
  (TA:171-181).
- Delivery before value: show the mechanism fires and its signature moves on paired cells before judging wins
  (TA:94-98; `tools/delivery.py`). Many rejects were mechanisms that never fired (c_seam2 matched c_seam1 on 100/100
  cells, TL:1455-1460; c_blind2's memory never fired, TL:2543).

### 1.5 How candidates were generated
- Target sources rotated (TA:70-85): own degeneracies (highest yield), the field (a contrast between bots that beat us
  and bots we beat), capability gaps (unused API), free actions and action patterns (owner, PR 49), structural swings.
- **One change behind a switch** in a constants class (`C.java`). Default = incumbent, so behaviour is identical with
  the switch off, checked with javap or identity games (TL:2280-2290, 2508-2520). Candidates were usually built with
  `tools/param.py make BASE NEW KEY=VAL` (HO:14-15, 121-125).
- **Diagnosis workflows**: multi-agent replay studies with 3-4 lenses, an adversarial verifier and a judge produced
  specs (research/diagnosis/*.md, e.g. 2026-10-18-structural-designs.md, 2026-10-19-top2.md, 2026-10-20-audit-c_gd1.md).
- **Ablation sweeps** (abl1-abl15): one switch off per build, the panel maps x both sides x 4 fixed seeds, paired
  against an identity build. About 80 games per switch, about 1,200 games per 15-switch sweep (TL:2263-2265, 2314; LRN:140-146).
- Owner-requested research: a Swiss tournament of random constants (PR 114), a successive-halving race of micro
  knobs (`tools/race.py`), a causal DAG of losses (PR 101), and an opponent-mimic archetype (PR 108). Results in section 3.

### 1.6 What the ladder replica was for and how it was used (HO:245-304; LS)
- A full private copy of the official contest website (galaxy: siarnaq backend plus the official frontend). Google Cloud is
  stubbed, egress is blocked, and nothing touches the official site (docs/galaxy/README.md:1-60; CLAUDE.md:21-26).
  The owner insisted we use it **as a contestant**, through the same API (submit, request, download), to rehearse
  the real contest (PR 11, PROMPTS.md:63).
- 87 field teams; autoscrims every 8 h; field bots challenge each other in idle capacity (HO:292-298). Hourly limits were
  raised from 10/10 to 40 unranked / 20 ranked (HO:254-256; PR 15-16).
- **Unranked for learning, ranked for banking** (LS:24-49). Ranked challenges go only from a validated build, to the
  team with the largest expected gain 24*(P_BT - E_galaxy) (LS:33-42). Pace: BURST (1 per 5 min) while there are
  fewer than 30 rated matches or the build is under 24 h old, else MAINTAIN (1 per 30 min) (LS:44-49).
- **The trap**: a match plays whatever submission is active when the match is created. A candidate is exposed to
  autoscrims and incoming challenges while active (LS:21-22). Fixes:
  - trials start right after an autoscrim and auto-reject incoming ranked challenges (LS:51-62);
  - **parked trials**: once all panel matches exist (about 1 minute), resubmit the validated build and let the panel
    play out, so trials overlap. This went from one trial per 8-hour window to several (LS:64-102; TL:946-953).
- **Panel versioning** (LS:106-138): the panel is fixed within a version and refreshed on triggers: an opponent at 9-10/10 or
  0-1/10, a BT expectation outside 25-80%, a whole panel above about 80%, or a map set narrower than the ladder's.
  - The control (the validated build on the new version) plays first.
  - v1 had 10 bots spread over the ladder on 10 maps. It saturated at 86/100 with 87 cells never flipping.
  - v2 used the 10 bots nearest us by BT on 100 distinct maps. v3 mixed sides per line (PR 137-138).
- Every downloaded replay was turned into a match report and a telemetry line (docs/TELEMETRY.md part C;
  research/matches/*.md; PR 13).
- BT over all games was the standing metric. The replica's own Elo was used for seeding only (LRN:91-94).

### 1.7 What changed over the project and why
- Day 1: arms were judged on 174 calibration cells against field bots, paired with g_iter0 (TL:72-95). Then the owner
  mandated "replica as contestant only", so local games became our own builds only (CLAUDE.md:42-46; PR 11).
- Day 2: 20-game pinned-seed self-play h2h. These cells turned out to favour the incumbent's seat 16-4, so "10/20 = neutral"
  was wrong and earlier closures were decided on a bad bar. Reads became paired against an identity run (TL:462-476).
- Day 2: pre-trial screen and archetypes added (owner, PR 22-23; TL:398-411).
- Day 4: parked, overlapping trials (TL:934-953). Reference bias found, so candidates were judged against two
  reference panels (TL:918-933).
- Day 8: an event watcher replaced the fixed 30-min task-check loop, to save cost and keep the session alive (TL:1379-1385; PR 88-90).
- Day 10: all-maps h2h (206 games) became the main local evidence. An ablation sweep found the largest late win (TL:2263-2272).
- Day 12: attempts ledger (PR 130). Screen (b) calibration: b >= 12 gives mean panel net +1.7, b 10-11 gives -0.3,
  b <= 9 gives -2.6, over 43 trials (TL:2262; LRN:147-150).
- Day 13-14: panel v2/v3, the t-based two-block rule, a ban on panel-only ratings (they run about 34 points high),
  random-seed h2h, and play-symmetry as a standing basics bar (TL:2591-2700; LS:106-157; LRN:29-38).

## 2. What worked (ranked by measured impact)

1. **A big swing: our own field-copied archetype became the bot** (c_swarm1, 10-08).
   - arch_swarm was built from replica replays of how the top bots played: mana-first economy, launcher-first opening,
     focus fire, a siege ring. Locally it beat the incumbent 17-3.
   - Panel: 40/100 vs 33, net +7 (+1.53 SE), and +9 vs g_iter0 (+2.32 SE). BT 1569 -> 1611 (TL:361-382; ATTEMPTS.md:45).
   - Echoes bc20: "copy the offence and submit it; build the defence against your own copy" (docs/ARCHETYPES.md:47-49).
2. **Navigation repair from an owner-spotted replay**: per-robot BFS distance fields over 64-bit wall rows, built in
   leftover compute (c_nav3/c_nav4; owner PR 35).
   - Panel 48/100 vs 40, net +8 (+2.31 SE). BT 1611 -> 1692 (TL:429-450, 499; HO:64-67).
   - Cause: greedy steps into pockets, and cohesion logic that reset the wall-following state.
3. **Anchor/objective discipline** (c_anc3: build anchors only for located targets, courier survival):
   panel 57/100, net +11 (p 0.003) (TL:607; ATTEMPTS.md:51).
   - Earlier anchor-gate fix c_line8a: anchors built 21.45 -> 9.95, carriers lost 28.5 -> 15.1 (ATTEMPTS.md:36).
4. **Ablating an early-accepted rule** (c_loose1 = launcher cohesion off; abl1):
   - net +20 (z 3.2) on the panel maps in self-play;
   - panel 79/100, net +6, strong bots 23/40 vs 17/40;
   - BT 1896 -> 2030 (TL:2263-2272; LRN:140-146).
5. **Basics fixes** (overruns, exceptions, stuck units):
   - c_nav6 removed launcher overruns in crowds; c_bc1 gave decision-preserving bytecode cuts, with the median march turn
     6,856 -> 3,664 (verified with an equivalence test of 217k cases). This headroom was a prerequisite: every
     launcher arm before it overran (LRN:160-162; TL:892-933).
   - c_aura2: our launchers killed by enemy HQ auras went 1,227 -> 35 per 100 games (HO:53-55).
   - Accepted even at net -2/-4 as basics fixes (HO:48-52).
6. **Economy fixes found by replay study, not by raising counts**:
   - well packing, c_pack1: net +4, carrier deaths -4.7 a game (HO:33-37);
   - contested-well squad and home-well defence, c_gp1: net +4/+8, carrier deaths -10.1 a game (HO:29-32);
   - healing on own islands, c_mend2: healed HP x2.2, t +4.8 (HO:44-47);
   - a near-well probe, c_well9.
   - In every one, the census showed the mechanism delivered.
7. **A stack of near-misses**: c_eco3 stacked abl3 economy near-misses. Self-play gave net +6; the panel gave net +3 with 0 lost
   (TL:2314-2334; HO:18-21). Stack positive near-misses, never things that were merely non-inferior (TA:108-109).
8. **The instrument fixes**, which were worth more than any single bot change:
   - the identity control and code-hash provenance caught an "identity" run that compiled changed code (TL:72-77);
   - the seat-bias discovery (TL:462);
   - the two-reference-panel rule (TL:918);
   - BT over Elo, shown on held-out games: log-loss 0.572 vs 0.628, +3.1 points accuracy, and the replica Elo of one
     unchanged build swung 191 points (TL:1363-1377; LRN:91-94);
   - the panel decision-rule simulation (TL:2591-2600).
9. **The causal DAG of losses** (owner, PR 101; `tools/causal_dag.py`) did not produce a bot change, but it correctly
   killed some arms:
   - adamantium was not a loss root (within-cell risk difference -0.19), so c_ad1 was held;
   - carrier count was not binding (c_cap1/c_thr1 rejected as predicted) (TL:1482-1510).
   - Its main finding: a mana gap from r100-200, then the army is behind, then the game is lost.

## 3. What did not work or wasted time

- **Self-play Swiss tournament of random constants** (PR 114): the winner c_tune1 scored net -8 on the panel and
  island-rounds t -2.71. Its screen h2h was 9/20. Self-play tournaments select against the field (TL:2000-2005; LRN:135-139).
- **Self-play win does not predict a panel win.** c_ms1 scored net +22 (t +3.18) on 206 random-seed cells against an
  identity build, but net +4 over two panel blocks (t 0.82), so it was rejected. A fix aimed at the incumbent's blind
  spot exploits only the incumbent (TL:2637-2642, 2675-2680; LRN:126-131).
- **Archetypes as gates never became valid.** 4 of 5 were just outside fidelity tolerances, and `archsig.py` was never
  built (HO:281-287).
  - No archetype's net tracked the panel against the teams it modelled (-0.31 to +0.26). Only the h2h (+0.45) and the
    pooled roster net (+0.42) tracked panel net (LRN:86-90).
  - The jmerle mimic (arch_jm, from state-action rows) reproduced 12/20 games. Its useful by-product was exposing
    our own Forest regression (HO:182-189).
- **Raising unit counts / caps / share ratios** (c_eco1/2, c_cap1, c_thr1, c_adlo2) lost every time. The binding
  constraint was carriers dying and mana per carrier, not build counts (TL:429-433, 1499-1510).
- **Copying a build order alone** (c_open1: the top bot's carrier-first opening) gave net -5. The copied build order did not bring the
  copied bot's economy with it (TL:1512-1538). The whole-style copy (swarm) worked; the one-trait copy did not.
- **Blind fire into clouds** (owner-observed free action; c_blind1/2) was inert: about 1% of damage, 20 outside-vision hits
  per game. The principle is fine; the expected value here was tiny (LRN:12-19; TL:1418-1453).
- **Micro tweaks**: GHOST, UHIT, focus-fire simulation (c_sim1 5/20), parity hold, commit margins, siege batches.
  Per-shot micro was already at parity with the strong bots; the losses came from army size (TL:2246-2261,
  research/diagnosis/2026-10-18-launcher-micro-vs-strong.md). The race found the knobs at a local optimum (TL:2047).
- **Narrow arms judged on general local screens**: an arm that acts only after r1700 or on one map reads as identity
  on the h2h. It needs cells it can change, or the panel (LRN:83-85; TL:955-962).
- **Self-play cannot judge levers aimed at strong-bot-only mechanisms.** Island levers changed 0-3 of 80 self-play
  games (abl4) (TL:2314-2320; HO:111-113).
- **Cohesion was found harmful twice.** On 10-08 cohesion off scored 15/20 vs on 7/20 (TL:303-306). But the swarm
  lineage adopted the same day carried its own cohesion, and only the 10-18 ablation removed it, worth +20 net. Ten
  days of drag. When switching lineage, re-apply known findings and ablate the new base (inference from TL:303 + 2265).
- **Deterministic map-seed self-play** made "per-map side bias" and many h2h verdicts mostly replays of one game.
  The same side won both games of a paired cell 75.8% (map seed) vs 52.6% (random seed) (LRN:68-73; TL:2644-2660).
- **Accepting at panel net +1..+3**: about 44% of null candidates pass. Several accepts (c_hr1 +1, c_isle1 +1, c_adp1
  +1, c_gd1 +3 at +1.0 SE) were probably noise (TL:2591-2600). And panel v1 saturated: late builds beat their BT
  expectation on its maps (+12.7 wins in 133) and fell short elsewhere (-40.6 in 1,382) (LRN:151-156).
- **A BT rank-1 claim came from panel-only games.** After a refresh, c_gd1 was rank 11 (TL:2615-2625; PR 133).
- **Operations losses**:
  - On 10-12 18:48 the replica and VM queue runner died silently. Screens sat pending about 40 h unseen (LRN:193-198; TL:1398-1406).
  - Usage ran out mid-week (PR 76-80); the first week burned about 265M units in 4 days, 56% of it one-off setup (TL:1351-1361).
  - A day (10-12) went on a Codex/web-worker access detour (TL:1041-1140; PR 51-71).
  - A stuck ranked match froze all ratings for 7-21 h, several times (TL:670, 1363-1377; HO:177-179).
  - Disk filled repeatedly (TL:1440-1445, 2026).
  - `timeout` around trial-start killed a panel block (TL:2272-2275).
  - `pkill -f` killed the calling shell (HO:329).

## 4. Infrastructure and tooling worth porting

Y = year-agnostic as is; A = adapt (game-specific parsing or API); N = 2023 or replica specific.

### 4.1 Statistics and ratings (Y, stdlib Python)
- `tools/elolib.py` + `tools/elo.py`: a batch Bradley-Terry fit (MM, Elo scale, a prior against a 1500 anchor, pair cap
  200, repeated cells deduped, each build its own player). Writes progress/ELO.md with field score and "vs higher".
  - Audited by 19 agents; 58 tests in `tools/test_elo.py` (research/audits/2026-10-10-elo.md).
  - Known issue: the prior compresses the scale by 13-19%; prior 0.1 recovers the slope (audit table).
- `tools/paired.py`: paired cells, gained/lost/net, SE = sqrt(g+l), D, t, sign p. It refuses mismatched cells files,
  coverage under 90% and incomplete runs.
- `tools/sprt.py` (SPRT on wins/losses), `tools/statlib.py`, `tools/delivery.py` (paired mechanism metrics),
  `tools/compare.py` (game-by-game run diff, identical cells, flips).
- `tools/causal_dag.py`: Mantel-Haenszel within-cell risk differences, giving the "trail by T in X at round R" loss roots.
  A, because it needs a timeline extract.
- `tools/field_score.py`: field score over time with an R0 + a ln(1+t) fit projected to week ends.
  `tools/rating_history.py` (A, replica API).
- The panel decision-rule simulator (two blocks, D ~ Poisson) lived in a scratchpad (seqsim.py) and should be
  re-written as a tool (TL:2595).

### 4.2 Game running (A: engine invocation)
- `tools/gauntlet.sh` + `tools/lib.sh`:
  - parallel bare-JVM games from a CELLS file of "opp map side seed" lines;
  - a private class tree per run, a wall-clock cap, KEEP_ALL, MAXJOBS;
  - results.csv with header `opponent,map,bot_side,winner_side,rounds,bot_result,reason,seed`;
  - provenance.txt with code hashes.
- `tools/get-engine.sh`: a checksum-pinned engine plus a one-class patch that honours a `-Dbc.game.seed` per game. Without
  it, (bots, map, side) fully fixes a game. **Check the new engine's seeding first** (TL:22-25).
- `tools/bot-hash.sh` (code hash invariant under package name), `tools/snapshot.sh` (freeze src/bot as a package),
  `tools/build.sh` (HASHES=1).
- `tools/param.py`: constants overridden at build time (`space`, `make`, `sample`). It is the backbone for ablations,
  `tools/swiss.py` and `tools/race.py` (successive halving).
- `tools/screen.py` (1,212 lines): the staged pre-trial screen, a reference-game cache keyed by code hashes, records
  in progress/screens/, exit codes 0/1/2/3, and `calibrate`.
- `tools/scrim-cells.py` (random contest-like cells), `tools/summarize.py`, `tools/throughput.sh` (find the
  concurrency knee: K=8 gave 8.9 games/min on 8 vCPU; TL:28-29).
- VM orchestration (Y with host names changed):
  - `tools/vm.sh`, `tools/vm-run.sh` (setsid + nohup, pgid recorded) and `tools/vm-stop.sh` (kill by process group,
    refusing foreign groups);
  - `tools/vm-enqueue.sh` + `tools/vm-queue.sh` (a standing serial queue with flock, an idle filler job, back-off on fast
    failures) and `tools/vmjobs.py`.

### 4.3 Replay analysis and telemetry (A: replay format differs per year)
- `tools/replaydump/ReplayDump.java` via `tools/replay-dump.sh`, which recompiles on a source-hash change. It rebuilds state from
  events and writes extracts: timeline.csv (both teams every 10 rounds), engagements.csv (first hit, exchange),
  deaths.csv, trips.csv, hq.csv, tele_states.csv, and a per-game census row (docs/TELEMETRY.md:531-929).
- `tools/match_report.py`: every downloaded replay becomes an at most 8 KB markdown report (tactics of both teams, turning
  point) plus a JSONL line. `tools/telemetry_query.py` aggregates across matches by opponent, map, submission or phase.
- `tools/sa_extract.py`: state-to-action rows of one opponent, for behavioural cloning of a sparring partner.
- `tools/profile.py`: a side-by-side tactical profile of each team from a census. `tools/basics.py`: the basics battery
  over a census with a control.
- **Telemetry design** (docs/TELEMETRY.md:17-64):
  - Official runs strip indicator strings and dots. The bot therefore encoded a 6-bit state code per robot-turn into its
    own `bytecodesUsed` (the "bytecode channel", about 48 bytecodes a turn) so that contest replays still carry decisions.
  - Telemetry always runs the same code, so local and contest games play identically.
  - Check what survives in contest replays for the new year: the owner was right to ask (PR 131), and it was re-verified.
- `tools/deadcode.py`: unreferenced methods and constants in a bot package. A never-called symmetry observer once made
  the symmetry a guess in about 30% of games.
- Per-year fixtures pin decoder numbers against the engine's verdict (TL:40-42).

### 4.6 Process tooling (Y)
- `tools/watch_events.py`: a background watcher that **exits** on PANEL_DONE, SCREEN_DONE, STUCK_MATCH (seen in RUN for

## 6. Year-agnostic principles distilled

1. **The target is the external field.** Self-play and archetypes are regression screens. Only a field panel (or the
   ladder) accepts. Self-play wins, including +22 net at t 3.18, did not transfer (LRN:126-139).
2. **Build the field and a contest-like ladder on day 1**, and calibrate the foundation bot against it the same
   day. BT over all games is the yardstick; the contest's Elo is noisy and compressed (LRN:91-94).
3. **Basics first, as absolute bars**: 0 compute overruns, 0 exceptions, symmetry correct and decided early, no stuck
   units, no floating resources, and **play symmetry**. Run a mirror match from both sides on every map; tie-breaks
   must come from the robot's own geometry, never compass order, ID or team (LRN:29-38; TA:46-51). Basics fixes may
   pass at net >= 0.
4. **Determinism is a tool and a trap.** Patch per-game seeds into the runner. Run an identity control on every verdict
   path. Use explicit random seeds, shared by both arms, for head-to-heads. Pair cell by cell; only discordant pairs count.
   Key results by code hash (LRN:68-73; TL:72-77).
5. **Pre-register and decide in t units with a simulated two-block rule**: t = net/sqrt(D), accept at t >= 1.5 and
   net >= +3, reject at net <= 0 after block 1. A single 100-game panel at net +1..+3 is noise (LS:140-157).
6. **Version the panel**: refresh it when it saturates (above about 80%, opponents at 9-10/10) or is map-narrow, run the
   control first, mark changes on charts, never quote standing from panel-only ratings (they run about 34 points high)
   (LS:106-138).
7. **Delivery before value**: prove the mechanism fires, and its signature moves on paired cells, before spending
   ladder games. Inert mechanisms were the most common silent reject.
8. **Ablate what you carry**, periodically and whenever you switch lineage. One switch off per build, paired with an
   identity build. A rule accepted early under other code became the largest drag (+20 net when removed) (LRN:140-146).
9. **Copy whole styles, not single traits.** A field-copied archetype became the best early jump. A copied build order
   alone lost (TL:361-382 vs 1512-1538).
10. **Measure productive capacity, not counts.** More units, caps or ratios never helped. Deaths, mana per unit and
    trip time did. Find the earliest round at which a metric predicts the result, stratified within cell (LRN:114-125).
11. **Every scarce game is diagnosis input.** Instrument the bot so contest replays carry its decisions (here a
    per-turn compute-count side channel). Report every downloaded match automatically (docs/TELEMETRY.md).
12. **Owner-visible state is part of the work.** Run one refresh command on every accept, commit and push in the same step,
    and make a failed refresh step fail loudly (TA:103-106; PR 119, 121).
13. **Every rule that can be forgotten becomes a tool that refuses**: trial-start without a screen, paired runs on
    mismatched cells, low disk, unreadable provenance (TA:148).
14. **Never idle, never wait.** Keep at least 3 queued jobs and an idle filler. An event watcher wakes the session. Liveness alarms
    cover every long-running component (TA:142-145; LRN:193-198).
15. **Budget context, not thought.** Agents queue long jobs and stop; a fresh agent collects. Keep wake-ups under the cache
    TTL, compact early, and use cheaper models for mechanical stages (LRN:164-172; TL:1351-1361).
16. **When rejects pile up in one area** (3), move on. At least 1 structural attempt in 4. On a plateau, follow the order:
    audit, ablate, API sweep, re-read the field, re-read principles, stack, rewrite (TA:123-138).
17. **Free actions always get a job; compare action patterns, not totals; in a live contest, lurk on Discord** (owner,
    PR 49). Audit them, but expect small value (blind fire was about 1% of damage).
18. **Treat a short owner question as an audit trigger.** Answer from data, and re-verify rather than defend (PR 131-132, 139).
19. **Pull ideas, don't just store them**: LEARNINGS.md holds year-neutral lessons with evidence; TRAINING_ALGORITHM
    names them as target sources; tools carry ideas better than prose (LRN:43-62).
