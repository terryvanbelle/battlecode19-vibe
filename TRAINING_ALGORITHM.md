# TRAINING_ALGORITHM.md — how this project gets stronger

Year-agnostic. It names no units, rules or tools of a particular season; `HANDOFF.md` maps each step to this year's
tools. Its sources are seven practice seasons (digests in `research/prior/`) and the cross-year `ADVICE.md`: every
rule below exists because a season lost time without it.

## 0. Objective and instruments

**Objective: absolute strength against the external field**, measured on a contest-like ladder. Beating our own
earlier builds is a means, never the goal.

| Instrument | Sees | Blind to |
|---|---|---|
| Rules digest (engine-checked) | what is possible | what wins |
| Replay reader + bot counters | one game in full: every unit's life, every decision | frequency, value |
| Paired self-play (candidate vs incumbent, same seeds, identity control) | marginal value and cost of one change | weaknesses both builds share; anything aimed at the field |
| Sparring archetypes (our copies of field tactics) | one behaviour each, reproducibly | everything else |
| Frozen roster (every accepted build) | a lineage walking downhill; non-transitivity | the field |
| Ladder (field bots, contest rules, batch rating) | strength and what the field punishes | why |

Never confuse them. When two disagree, run a third and report the disagreement, not a verdict.

## 1. Phase 0: the foundation (no strategy loop until every item passes)

Each instrument is proven on a case with a known answer before it judges anything.

1. **Rules digest** from the engine source, every fact tagged with its file and line. Read the legality checks and
   cost order of every action; list the season's real win condition and tiebreak from the first replay.
2. **Map corpus**: every map available (or generated), with features (size, symmetry, spawn geometry, resources,
   distances). Facts true on every map are constants, not sensor readings.
3. **Headless runner**: parallel, sandboxed (no network for any bot), one result row per game keyed by
   `(code hash A, code hash B, map, side, seed)` with winner, ending reason, rounds, exceptions, compute overruns.
   Measure the machine's concurrency knee and per-game cost.
4. **Determinism**: control every source of randomness we can. Identical code on the same seed must give the same game,
   or the residual noise must be measured and stated. **Identity control on every verdict path**: a byte-identical copy
   of the incumbent must read zero (or the stated noise floor of) discordant pairs.
5. **Replay reader**: per-round team aggregates as CSV; an event window; one robot's whole life; the board at a round;
   our own log lines; per-type compute maxima and overruns; navigation statistics (moves, stalls, oscillation,
   coverage). Fixture tests pin its numbers to the engine's own.
6. **Bot skeleton**: layered (shared utilities, then one module per role), one constants file where every behaviour
   change sits behind a switch defaulting to the incumbent, a per-robot seeded RNG, tie-breaks from the unit's own
   geometry (never compass order, id or team), a compute monitor in the turn loop from the first commit, decision log
   tags you can grep.
7. **Snapshot tool**: every accepted build frozen as an opponent forever; the working bot byte-identical to the
   incumbent between candidates.
8. **External field**: discovered, fetched, security-scanned and compiled by script, never read; smoke-tested against
   the starter bot.
9. **Ladder**: a private replica of the contest's judging site. We play it **as a contestant** through its own API:
   submit, request scrimmages, download results and replays. Field bots challenge each other in spare capacity.
10. **Charts and handoff** regenerated by one command that fails loudly; unit tests for the bot's pure logic and for
    every tool, run by one command after every change.
11. **Basics battery** — absolute bars, not trade-offs:
    - economy: no idle gatherers, no resource floating above a stated band, producers never starved or sealed;
    - movement: no unit stalled N turns without a log line, no oscillation, targets reachable;
    - exploration and symmetry: the enemy base located exactly as soon as observations allow (guessing what can be
      known is a bug); every candidate symmetry kept alive until refuted;
    - combat: focus fire, no friendly fire, no fights started at a local disadvantage;
    - **zero compute overruns, zero exceptions**;
    - play symmetry: a mirror of the bot against itself splits evenly on every map from both sides.

**Foundation bar:** beats the starter bot from both sides on every corpus map; passes the basics battery; submitted to
the ladder and calibrated with a full field block the same day. Then run a correctness audit (§6) once, before the loop.

## 2. The loop

1. **Pick a target** from the rotation in §3.
2. **Trace** the motivating replay with the reader, then check the same symptom in a second game against a different
   opponent. Enumerate the mechanisms that could produce it before choosing one.
3. **Pre-register** in the training log: the mechanism; the decision counter (a log tag) that shows it fires; that its
   branch is reachable at the values actually observed; how often its trigger fires across recent games; what it
   displaces; the deciding instrument and gate; the falsifier; a dose ladder with a byte-identical zero arm.
4. **Implement one change behind a switch.** Unit tests pass. With the switch off the build is byte-for-byte the
   incumbent in behaviour (checked by identity games).
5. **Delivery** (does it fire?): one logged game read against the incumbent on the same seed; then a small paired block
   whose counters show the mechanism fires in most games and its signature moves. A candidate that does not deliver
   never reaches a gate; the screen job prints the delivery counters beside its result.
6. **Local screen** (paired self-play): candidate and incumbent on the same random (map, side, seed) cells; only
   discordant pairs count. Also the archetype roster and the frozen roster. Once a ladder panel exists the screen
   **only rejects**: self-play wins that exploit the incumbent's own habits are reversed by the field often enough
   that no local number accepts. Reject at t <= -1.5, at a one-sided sign-flip test p < 0.05 on the per-cell
   difference in the graded objective (castles lost), or at any exception the incumbent does not have; overruns and
   frozen units are read per million turns against the incumbent's, since the machine causes most of them. Together
   the bars reject roughly one neutral candidate in eight (the t bar alone 3-13%, swinging with D); a bar that rejects
   one in three (an uncalibrated ratio) costs more good candidates than the panel time it saves. Everything else goes to step 7.
7. **Ladder panel**: an unranked block against field bots near our rating in strength (the bots that beat or split
   with the incumbent lately, not the rating list alone), on maps drawn once per opponent and kept, every cell played
   **from both sides** (the side to move first can matter more than a candidate). Where a match keeps the build it was
   created with, submit the candidate only while its matches are created, then resubmit the incumbent. Score by the
   pooled rule (§4); a block is scored only once all its games have finished.
8. **On accept**: snapshot; submit as the active build; run the progress refresh (ratings, charts, attempts table,
   handoff); commit and push the same hour; mine the new ladder games for the next target.
9. **On reject**: restore the working bot from the snapshot, log the closing number, its kind (refuted, below
   resolution, blocked on a prerequisite, inert) and a checkable re-open condition in the closed-directions ledger.

Near-misses (positive estimate, delivered, independent mechanisms) may be **stacked** and tested as a new arm. Never
stack changes that were merely "not worse".

## 3. Where candidates come from

Rotate among these so none dries up; highest yield first.

1. **Our own degeneracies**, visible without any opponent: idle or frozen units, floating resources, stalled
   production, oscillation, overruns, exceptions, units dying to something avoidable. Repairs of defects and removal of
   binding caps transferred to the field in every season; reallocations between unit types mostly did not.
2. **The field**: tactics opponents beat us with (copy the offence, submit it, then build the defence against our own
   copy); a contrast of behaviour rates between bots that beat us and bots we beat; the earliest round at which a
   metric's lead predicts the result, stratified within opponent and map.
3. **Capability gaps**: API calls and rules we never use; free actions that have no job; unspent compute.
4. **Ablation** of what we carry, periodically and after any change of lineage: one switch off per build, paired
   against an identity build.
5. **Structural swings**: a different economy, opening or army doctrine; a whole field style adopted (copy whole
   styles, not single traits); a rewrite that keeps the proven plumbing.

Balance rules: **at least one structural attempt in every four**; **three consecutive rejects in one functional area**
(economy, production mix, navigation, exploration, combat, communication, defence, map adaptation) move the next
attempt to another area or to the structural track. Before building a fix diagnosed on one replay, estimate how often
its trigger fires elsewhere.

## 4. Statistics

- The unit of evidence is the **paired cell** `(opponent, map, side, seed)`, candidate vs control on the same cell.
  Identical outcomes carry no information. With D discordant cells and net = gained − lost, t = net / √D.
- **The control is a sample too.** Where the ladder's games are not deterministic, one control block mislabels cells:
  a candidate "loses" the cells the control won by luck and "gains" those it lost by luck, and every neutral candidate
  reads net ≈ 0. Pool each cell's record over the incumbent's own blocks and the neutral rejected candidates' blocks,
  and score a candidate by wins minus the pooled expectation: z = (W − E) / √V, E = Σ p, V = Σ p(1 − p).
- **The cell includes the side.** p per (opponent, map, side) = (w_s + k·p_c) / (n_s + k), k = 2, where
  p_c = (w + ½) / (n + 1) is the side-blind cell rate: the side's own record, shrunk toward the cell's while it is thin.
- **Pooled rule**: after block 1 reject at z < 0.5; after block 2 accept at cumulative z ≥ 2, reject at z < 1, else a
  third block, accepted at z ≥ 2. A rejected candidate's block joins the pool only when its own z lay within ±1 (a
  clearly worse candidate's block lowers every later expectation). A fix that removes a basics failure may be
  accepted at z ≥ 0. Simulated on a real pool redrawn every trial (so the pool's own noise counts), these bars on
  36-game both-sides blocks accept a neutral candidate 7% of the time and one worth +1 / +1.5 / +2 wins per 18 games
  45% / 70% / 85% of the time, in about two blocks; 18-game blocks with one random side per cell reach 28% / 46% / 66%.
- **The pool is not a test set.** A candidate designed from particular panel cells lists them in its pre-registration;
  it is accepted only if its z over the other cells is ≥ 0 as well. Version the panel (§5) before every cell has
  been studied.
- **No rule applies backwards.** A rejected candidate is never reopened under a rule written after its rejection
  without fresh blocks, and a decision rule is fixed in the log before the block it decides is scored.
- Where the season has a graded objective (score margin, structures killed, resources at the end), test the per-pair
  difference in that objective alongside wins: it carries several times more information per game.
- Local paired reads: size by discordant cells, not games: with a deterministic engine, a switch that never changes a
  decision on a map gives byte-identical games there, a split by construction. Count them (compare the two replays
  of each cell); where D stays small, add cells until it reaches a fixed target before reading t. Stopping on D,
  which says nothing about who won, does not bias t.
- Simulate every bar's false-reject rate, and every panel design's false-accept rate and its power at a realistic
  effect (one to two wins per 18 cells), before relying on it; a design that cannot pass a real gain is a defect.
- Rating: batch Bradley-Terry over all ladder games, each build its own player, a weak prior, repeated cells counted
  once, a cap per pair. Report rating with interval, rank, and expected score against the whole field. The contest
  site's own sequential rating is for seeding only.
- Never read a running batch. Never move a bar after seeing a number. Never reinterpret a null. A single fixed-seed
  game is a filter, never a verdict. Read the shape of a diff: one-directional on one map or side is real; scattered
  and mixed is noise. Pool only the incumbent's lineage (its own blocks and its neutral candidates), never an older
  champion's history. An agent given replica data gets finished matches only.

## 5. Using the ladder like a contestant

- Only validated builds play ranked games. Candidates play unranked panels, timed so the candidate is active for as
  short a time as possible (park it as soon as its matches exist).
- Rotate opponents from the band around our rating, random map and random side, so results inform in both directions.
  Never pick a map or a side for advantage: panel maps are drawn at random once per opponent and kept, and every
  panel cell is played from both sides.
- Version the panel: refresh it when it saturates (any opponent at 0–10% or 90–100%, the whole panel above ~80%) or is
  map-narrow; play the control first; mark every version change on the charts. Never quote standing from panel games
  alone.
- Every downloaded replay becomes a short match report (both teams' tactics, the turning point) and a census row. The
  ladder is read for ideas, never waited on: work continues locally while its games run.

## 6. When nothing is accepted (the plateau protocol)

Escalate in this order; do not skip to the end.

1. **Correctness audit** of the bot and of the instruments: independent lenses (dead code; rules and API; shared state
   and communication; behaviour in replays; the measurement pipeline), every finding with evidence, a fix and a
   regression test, and a separate reviewer trying to refute it. Prove the instruments with an identity control.
2. Ablate everything we carry.
3. Sweep the API and engine for unused mechanics.
4. Re-read field replays for what we were not looking for; build the archetype that beats us.
5. Re-read cross-year principles (`ADVICE.md`, `LEARNINGS.md`).
6. Look for a jointly necessary pair among recent near-misses.
7. A structural attempt; then a rewrite that keeps the plumbing. A rejected structural attempt is an ordinary outcome.

A closure says an implementation failed; only a ceiling (arithmetic, engine) licenses abandoning a line.

## 7. Operations

- **Never idle.** Keep at least three jobs queued on the compute machine and an idle filler that plays the shipped
  build on fresh cells. A background watcher wakes the session on finished work, a stuck or dead component, low disk, or
  a heartbeat; it is re-armed at the end of every turn.
- **Rules live in tools that refuse**, not in memory: no paired read on mismatched cells, no pooled score of a block
  with an unfinished game, no result row without code-hash provenance; the screen prints its own verdict.
- **Records**: an append-only training log (one entry per attempt: target, trace, pre-registration, counters, gate
  numbers, decision, what it closed, next); a closed-directions ledger; `LEARNINGS.md` for durable lessons, each with
  its measurement; an attempts table with every funnel stage; `HANDOFF.md` as a closure map. Record the measurement,
  not the story. Nothing stale stays.
- **Owner**: every prompt verbatim in `PROMPTS.md` (PDT); progress visible in the repository at every accept; a short
  owner question is an audit trigger, answered from data.
- Kill ideas cheaply, in this order: engine read, census of replays on disk, one-map probe, small paired block, local
  screen, ladder panel.

## 8. Defaults

| Parameter | Value |
|---|---|
| Delivery block | 24 paired cells, extend to 48 |
| Local screen | 20 paired cells (both sides); rejects only: t ≤ −1.5, castles-lost sign-flip p < 0.05, a new exception |
| Ladder panel block | 6-8 field bots near our rating × 3 maps × both sides; pooled side-aware z of §4 (0.5 / 2 and 1 / 2) |
| Rating pair cap | 200 games per pair |
| Area switch | 3 consecutive rejects |
| Structural share | ≥ 1 in 4 attempts |
| Basics | 0 overruns, 0 exceptions, mirror even on every map from both sides |
| Watcher heartbeat | ≤ 50 minutes |
